# antislop audit 001: flownarrate.com

Date: 19 Oct 2026
Mode: AFTER (audit only, nothing changed yet)
Scope: all 23 HTML pages (root pages, `tools/`), `assets/tools.css`, `assets/tools.js`

## How it was checked

- Read the source of every page and grepped for the antislop patterns: em dashes, arrows, buzzwords, generic CTAs, statistics, testimonials, FAQ, `outline: none`, grid backgrounds and hard-coded colours.
- Loaded every page in headless Chromium in 4 setups: light and dark, at 1280px and 375px. Each run checked horizontal overflow, JS console errors, text contrast (WCAG AA, computed against the real background) and the size of every control at phone width.
- Took screenshots to confirm the dark-mode diagram problem in finding 1.

## What already passes

- No horizontal overflow on any page, in either theme, on desktop or phone.
- No JavaScript errors on any page.
- No buzzwords, generic CTAs ("Get Started", "Learn More"), invented statistics, testimonials or template FAQ anywhere.
- Credentials link to Microsoft Learn and Credly, so they can be checked (R-17, R-36).
- Skip link, visible `:focus-visible` outlines and no `outline: none` (R-32). Motion respects `prefers-reduced-motion`.
- The theme toggle works and defaults to the OS setting. Contrast passes everywhere except finding 3.
- Strong identity. The "Run summary · your last flow" hero, the plum accent and the run-status vocabulary would not survive a logo swap (R-20). The homepage sections each have a different layout (R-05).

## Findings

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

### HIGH

**1. Approval-post flowcharts break in dark mode (R-34).**
`narrating-an-approval-flow.html` lines 378 to 504: the three SVG diagrams hard-code `stroke="#1A1A17"` and `fill="#4B4B44"` for box outlines and arrowheads. In dark mode the panel is `#1B1B21`, so outlines and arrowheads disappear and only the text and green/orange boxes remain (confirmed by screenshot). The green `#2F6B3F` and orange `#B54708` are also fixed, so they don't change with the theme. Fix: use `currentColor` / `var(--ink)`, `var(--ink-soft)`, `var(--ok)`, `var(--warning)` via classes, as CLAUDE.md asks.

**2. Em dashes in post copy (R-02).**
`do-not-reply-mailbox-dataverse.html` lines 416, 463 and 464 use `&mdash;`. Replace with a colon, comma or parentheses. (The one in `assets/tools.js:1059` is inside a regex that reads pasted input, not visible text, so it stays.)

**3. Text below 4.5:1 contrast (R-25).**
`microsoft-forms-pre-filled-links.html` lines 377 to 379: the green `.ok` highlights (`FORM-ID`, `"No"`, …) inside the dark code block measure **3.28:1** in light mode. The code block background is a fixed dark `#1A1A17`, but `--ok` switches to dark green in light mode. Fix: give the code block its own fixed light-on-dark highlight colour, or theme the block.

**4. Blog filters have no empty state (R-27), and offer categories with no posts.**
`blog.html` lines 326 to 332 and 411 to 417: "Quick Tip", "Certification Corner" and "Opinion" have no posts. Clicking one empties the grid with no message. The homepage filter already does this properly ("Nothing on this topic yet. It's on the list."). Fix: reuse that empty message, or hide pills with zero posts. Also expose the selected pill with `aria-pressed` like the homepage does. At the moment only a CSS class marks it, so screen readers can't tell which filter is active.

**5. Tap targets under 44px on phones (R-03).**
Measured at 375px:
- Menu button `.nav-toggle`: 38×32 (every page)
- Blog filter pills: 34px tall
- "Copy request" / "Copy Mermaid code" / "Change answer" buttons: 34 to 36px tall
- Footer links (Privacy, RSS, LinkedIn, flownarrate.com): 16px tall
- Breadcrumb "Tools" link on tool pages: 16px tall
- `<summary>` toggles ("View as Mermaid", "Sample Web API request"): 21px tall
- Brand link: about 26px tall

The homepage filter buttons and `.btn` already use `min-height: 44px`/`48px`, so the pattern exists. It just needs applying to these.

### MEDIUM

**6. Graph-paper background on diagrams has no written reason (R-07).**
`.flowchart` in `narrating-an-approval-flow.html:255` and `assets/tools.css:319`. There's a good case for keeping it (it reads as a diagram canvas, like the flow designer), but the reason should be written down (see finding 10). Keep or drop: your call.

**7. Uppercase, letter-spaced monospace labels have no written reason (R-06).**
Nav links, `.kicker`, `.rs-head`, `.post-format`, `.meta`, `.fc-label`: JetBrains Mono, uppercase, 0.05 to 0.08em tracking. Moderate tracking, and it plausibly echoes Power Automate's run-history UI. If that's the reason, write it down and keep it. JetBrains Mono is also on the "AI default" list, so its reason belongs in the same note.

**8. Arrows on link buttons (R-08).**
`→` appears on "Read a narration →", "All posts →", "All tools →" (homepage) and "Browse every tool →" (all 13 tool pages). It's only on "go to the list" links, not every button, so it's restrained. It's still decoration without a written purpose. Either keep it as a deliberate "go to the index" signal (and write that down) or remove it.

### LOW

**9. Dead CSS and hard-coded colours in `index.html`.**
Lines 142 to 263 and 391 to 507 style things that aren't on the homepage (`.mermaid-code`, `.expr-tool`, `.filter-row`, `.tools-card`, `.flowchart`, `.credentials`, `.badge`, `.posts`). Some of it uses raw hex (`#1A1A17`, `#9E3B32`), which goes against your CLAUDE.md colour rule. The variables `--bronze`, `--pink`, `--magenta`, `--plum`, `--amethyst` and `--accent-hover` are defined but used nowhere on the site. This is leftover from copying, and harmless on screen, but it makes the palette look larger than the two colours it really uses (R-29, C-1).

**10. No `DESIGN.md` recording the design direction (R-31).**
The site clearly has a direction ("Run status" palette in CLAUDE.md, a "Direction D" comment in `index.html`), but the reasons behind type, layout, labels, grid and callout stripes aren't written down anywhere. A short `DESIGN.md` in your words (I can format your answers, not invent them) would settle findings 6, 7, 8 and 11, and stop future edits drifting. Suggested dial from what's live: ENERGY 1 / RHYTHM 2 / MOTION 1.

**11. Coloured left stripe on callouts (Part 1 pattern, R-31).**
`.callout` has `border-left: 3px solid var(--succeeded)` on the three posts, plus a warning-coloured one in the approval post and `assets/tools.css:574`. The `.recreation` stripes in the mailbox post carry meaning (red = failed, green = ok) and are fine. The plum callout stripe is decoration. Keep it if it's meant to be a "narrator's aside" marker, and write that down.

**12. Homepage promises formats that don't exist yet (C-3).**
"What gets narrated here" lists Case Studies, Agentic AI, Certification Corner and Quick Tips, and none have posts yet. The homepage filters show "AI agents (0)" and "Certification (0)". It's honest (the empty state says so), but a reader can't tell which formats are live. Option: mark the unpublished ones "first one coming", or list only live formats.
